# Tileset and sprites

A map tile (`TILE_SIZE`) is **32px**. The art comes in two forms:

| Art            | Files                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Size                                          | Drawn as                                                                                                 |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Terrain        | `src/assets/overworld.png` (made from the Tactical RPG Overworld Pack sheet)                                                                                                                                                                                                                                                                                                                                                                                                                    | 32x32 tiles, 42x63 sheet                      | Phaser tilemaps: grass base plus half-tile autotile layers                                               |
| Units          | `src/assets/units/` (16 units x 6 versions, see [units-catalog.md](units-catalog.md)); each version is a faction (`factions.ts`), so a faction class wears `FACTION_BODIES[class]` + its faction's variant (`getUnitSprite`, e.g. `Soldier_02` for sunward); the elementals use `Elemental_01`–`_04`; the monsters `Slime`, `Goblin`, `Skeleton`, `Bat`, `Orc`, `Minotaur`, `Troll` have their own sheets and the red dragon boss `Red_Dragon` (all with their own frame sizes, see `UNIT_ART`) | 4x4 sheet of 32x32 frames, one row per facing | Sprite looping its facing row's frames (`UNIT_SHEET`, `UNIT_ANIMATIONS`)                                 |
| Trees          | `src/assets/gold_ginkgo_tree.png`                                                                                                                                                                                                                                                                                                                                                                                                                                                               | 32x32                                         | One sprite per tree (`TREE_SPRITES.gold_ginkgo`) over a blob shadow (`TREE_SHADOW`)                      |
| Trees          | `src/assets/ginkgo_tree_green.png` (the same drawing in green)                                                                                                                                                                                                                                                                                                                                                                                                                                  | 32x32                                         | One sprite per tree (`TREE_SPRITES.green_ginkgo`)                                                        |
| Item icons     | `src/assets/items/` (one per item id: the wooden set, plus every other weapon, staff, potion and the seal)                                                                                                                                                                                                                                                                                                                                                                                      | 32x32                                         | `ITEM_SPRITES` maps item id to texture key (`getItemSprite`): the roster screen's and unit panel's icons |
| Cursor         | `src/assets/overworld.png` tiles `[28, 62]` and `[29, 62]`                                                                                                                                                                                                                                                                                                                                                                                                                                      | 32x32                                         | Sprite looping the two tiles (`CURSOR_ANIMATION`)                                                        |
| Movement arrow | `src/assets/overworld.png` tiles in columns 29–31, rows 56–60 (`ARROW_TILES`)                                                                                                                                                                                                                                                                                                                                                                                                                   | 32x32                                         | One sprite per route tile, drawn from the sheet                                                          |

The arrow is a continuous 8px pink band through tile centers. Straights and rounded corners come from the pack's pink rounded-square loop (a 3x3 of path tiles around a gem), and the heads from the tiles just below it. Pieces are named after `src/game/moveArrow.ts`: `head-up`, `head-down`, `head-left`, `head-right`, `left-right`, `up-down`, `up-left`, `up-right`, `down-left`, `down-right`. Each corner piece is named for the two tile edges it joins. The sheet also has a _broken_ (segmented, directional) arrow set in rows 50–55, which we don't use; see [ui-catalog.md](ui-catalog.md).

## Units: idle and move sheets

**[units-catalog.md](units-catalog.md)** lists every unit sheet in `src/assets/units/` (the whole pack: 16 units, six versions each, one per faction) with what it shows, its footprint, and what to check before using it. Read it before picking unit art.

Each unit art (`UNIT_SPRITES`, e.g. `Soldier_03`) has one sheet per animation in `src/assets/units/`, named `{Unit}_{NN}_{Animation}.png` after the source pack: `_Idle` and `_Move`. The texture key is the file name without `.png`, built by `unitSheetKey(art, animation)`. Every pack sheet in the folder is already at 2x (the monsters' sheets are 2x too, downscaled from 3x). Both are 128x128 sheets of 4x4 32px frames with the same layout. Each row is a facing direction, each column an animation frame (idle: a small bob; move: a walk cycle, with the body shifted 1–2px and the feet alternating). Rows, top to bottom: **down** (toward the camera), **left** (west), **right** (east), **up** (back to the camera). Left vs right was read from the pixels: in row 1 the face, the single visible eye and the soldier's visor sit on the left, the hat's tip / ears trail to the right, and the soldier's spear points lower left; row 2 mirrors it. The source PNGs are RGB with a `tRNS` color key making black transparent. Feet: the villager's bottom outline is x 10–21, y 28–29; the soldier's is wider (a spear sticks out lower left) down to y 31.

Art cut otherwise (bigger frames, more animations: attack, hit, die) is listed in `UNIT_ART` in `tileset.ts`; the monsters (`Slime`, `Goblin`, `Skeleton`, `Bat`, `Orc`, laid out by `monsterArt(height, impactFrame)`; `Minotaur`, `Troll` by `bigMonsterArt`) and the red dragon `Red_Dragon` (see the catalog), whose sheets load at their own frame size, pinned by the unit's tile. `GridScene` loads every other sprite in `SPRITE_URLS` as a 32px spritesheet and plays `<sheet key>-<facing>` on each unit (e.g. `Villager_02_Idle-down`), keeping the unit's art and facing in the sprite's data. Units start out facing `defaultFacing` (down); `walkSprite` plays the move animation facing each step (`getPathFacings` in `src/game/facing.ts`), then idles facing the last step. The React `UnitSprite` crops the default facing's row of the idle sheet out of the sheet with a CSS background, showing its first frame, or with `animated` looping the same idle frames as the map (the deployment roster uses this).

## Trees: gold ginkgo sheet

`gold_ginkgo.png` is 131x131: 16 variants of a golden ginkgo tree in a 4x4 grid of 32px frames with a **1px transparent gutter** between them (frame origins at 0, 33, 66, 99); the game doesn't load it (Phaser would need `spacing: 1`). Each frame is one whole tree: a yellow-gold canopy (`#fdd633` / `#dd980f`, outlined `#31161c`) over a dark brown trunk, standing on its own ellipse of grass (`#a6ce5d` with a `#6f9e43` rim) that fills the bottom ~10 rows. Content spans x 1–30, y 0–31 in rows 0–2; the bottom row's frames stop at y 29 (the sheet is cut off, so their grass ellipse is missing its last 2 rows). Some variants have extras on the base: variant 9 has a small pond (`#638ea7` / `#c1dce1`) at lower right, variant 14's trunk has a dark root/branch reaching right. `gold_ginkgo_tree.png` and `ginkgo_tree_green.png` are the same drawing in two colorways, made to match the terrain sheet: **16px art doubled to 32x32** (every art pixel is a 2x2 block), three flat sheet colors each, the dark leaf tone doubling as the outline. The canopy is a heart-shaped fan like a ginkgo leaf — two lobes with a notch at the top and a dark center vein — spanning x 0–31, y 2–23, with a few dark leaf dots; the trunk (`#8f4d57`, the pine tile's trunk brown) is x 14–17, y 22–27 with a foot at x 12–19, y 28–29, and rows 0–1 and 30–31 are empty. Green uses the pine forest's `#3b7d4f` / `#84b14d`; gold uses the sheet's amber pair `#cf752b` / `#f0b541`. Neither has a grass patch, so each is drawn over `TREE_SHADOW`, a translucent ellipse at its foot. (They replaced a true-32px, ~28-color painterly ginkgo that didn't match the sheet.) `green_ginkgo_tree.png` is a separate 4x4, 1px-gutter sheet of green trees (same layout as `gold_ginkgo.png`, bottom-row frames run y 1–30) that the game doesn't load. The demo level places the gold tree and its green recolor at `TREE_POSITIONS` in `demoLevel.ts`; `GridScene.renderDecorations` draws them over the grass at depth 0.4, each over its shadow (`addTreeShadow` in `src/scenes/unitShadow.ts`, depth 0.35), and they don't block movement.

## Item icons: src/assets/items/

One 32x32 PNG per item, named by item id, painted at a true 32x32 (not 16px doubled), transparent background, no shadow, alpha snapped to fully on or off. Generated with PixelLab: `create_image_pro_flash` at 32x32, `max_colors: 16`, the old 16px-doubled `iron-axe` as the style image for outline and shading only; prompt: the subject plus "single centered object filling most of the canvas, detailed GBA-era 16-bit RPG item icon, single color dark outline, rich shading with highlights, no shadow, no background" (weapons "lying diagonally with the business end at the upper right"). Each keeps its own colors. Weak spots: `wooden-spear` is very thin, `wooden-sword` and `club` sit small on the canvas, `bite`'s jaws read loosely, and `ballista` is drawn as a wheeled catapult. The raw outputs and `prompts.txt` are on the art machine under `pixellab/rogue-emblem-icons32/`. `src/game/tileset.test.ts` fails when a run item or weapon has no icon.

## Reward icons: src/assets/rewards/

One 32x32 PNG per reward kind whose card doesn't show an item or unit (`draft`, `rest`, `relic`, `gold`, `lesson`, `scroll`), named by kind, made with the item icon recipe above: a stack of ribbon-tied contracts with a wax seal, a campfire, a gold amulet with a purple gem, a heap of gold coins, an open book under a glowing blue star, a sealed scroll. ## Glyph icons: src/assets/glyphs/

20x20 PNGs, transparent, one per `GlyphKind` and per `StatIconKind` (named by kind, e.g. `crit.png`, `rout.png`). Most were painted with PixelLab in the item icons' style (dark outline, a few shades); `auto` (fast forward), `exp`, `health`, `gold`, `skull`, `danger`, `attack`, `move`, `book`, `skill`, `heal` (red cross), `item`, `settings`, `music` (note), `avoid` and `mp` are the UI asset sheet's dark-outlined 10x10 icons (its bottom icon set; the plain and gold-glow sets above it are unused) doubled, written by `scripts/slice-ui-sheet.js` (rerunning it overwrites them). The painted ones are 16x16 art centered with a 2px transparent margin. `hit` is a painted red-and-white bullseye: the sheet's own target icon read as the Instagram logo, so the script leaves it alone. Shown at 1x (20 CSS px), 12px in the reward tiles' EXP and the merchant's prices (smoothed there, since pixelated 0.75x drops rows). `glyphIcons.test.ts` checks every kind has one and each is 20x20. `range.png` (a dotted arrow) is the weakest and the first to repaint.

## Boon icons: src/assets/boons/

One 32x32 PNG per level-up boon (`BOONS` in `src/game/warband/boons.ts`), named by boon id (`stat-health`, `skill-cleave`, `keen-eye`, ...): 16px art doubled, transparent background, no shadow, alpha snapped to fully on or off. Generated with PixelLab (`create_image_pro_flash` at 16x16, `max_colors: 12`, the wooden sword halved to 16px as the style image for outline, shading and detail only, not colors; prompt: the subject plus "single centered object filling most of the canvas, chunky GBA-era 16-bit RPG item icon, single color dark outline, basic shading, low detail, no shadow, limited palette"), then upscaled 2x. Unlike the wooden items they keep their own colors (each is its subject's color: a red heart, a green clover, a blue crystal...), and with `max_colors` set they need no palette snapping. Stat boons show their stat's symbol (heart, flexed arm, tome, bullseye, winged boot, clover, kite shield, amulet), skill boons the weapon or motion, passives a symbol of the effect. The eight build-synergy passives were drawn instead in the general icon set's style with the pxl stand-in (source in the project files under `art/gear-icons/src/boon_icons.px.js`): `bloodlust` a double axe with bloody edges, `exploit` a dagger stuck in a cracked bullseye, `opportunist` an eye with a bullseye iris and a glint, `thorns` a thorny green branch, `spite` a round mirror shield, `desperation` a cracked heart, `soul-harvest` a sickle with a blue wisp, `trophy-hunter` a horned skull on a plaque. Weak spots: brawler's gauntlet spikes barely show, quick-study is a plain scroll (its star didn't come out) and regeneration's plus is a yellow speck. Only React shows them (`BOON_ICON_URLS` in `src/assets/boonIcons.ts`, a Vite glob, not `SPRITE_URLS`); `src/assets/boonIcons.test.ts` fails when a boon has no icon or an icon has no boon. The raw PixelLab outputs and their prompts are in the project files under `art/boon-icons/raw/`.

## Gate: gates.png

`src/assets/gates.png` is 96x64 (3x2 tiles): one red Chinese-style paifang gate with a tiered roof and a gold plaque in the middle, drawn within x 3–85, y 3–56 (transparent margin around it). It was the top-left cell of a 192x128 sheet of four gate variants (a 2x2 grid of 96x64 cells), cropped down at the user's request. Its posts stand at x ~10–13, 27–30, 58–61 and 75–78, so the opening under the plaque is the middle tile column (x 31–57). The game draws it as `STRUCTURE_SPRITES.gate` (texture key `gates`, 3x2 tiles): Like every sprite it loads as a 32px spritesheet, so its six tiles are frames 0–5 in reading order. `GridScene.renderStructures` draws it tile by tile from `getStructureTiles` (`src/game/structures.ts`): the top `roofRows` row (the roof and plaque) at depth 0.8, over units (0.75) and under the cursor (1), so a unit in the opening's top tile stands behind the roof (only its hat tip shows above it); the bottom row (the posts) at the trees' depth 0.4, under units. Level 1 (`demoLevel.ts`) puts it at the north end of the dirt path; all six of its tiles are walkable, so units can stand behind the roof or by the posts on any column.

## Terrain: overworld sheet

**[overworld-catalog.md](overworld-catalog.md)** lists the map art on the sheet: grass variants, the water, sand, dark-grass and deep-water sets, island rings, mountains, forests, bridges, team-colored buildings and walls. Read it before picking any terrain art. The UI pieces on the same sheet (cursor, movement arrow, digits, HP bar, markers) are in **[ui-catalog.md](ui-catalog.md)**, kept separate so they're never mistaken for map tiles.

The sheet comes from a pack drawn at 3x (every art pixel is a 3x3 block, so it's natively 1024x1024, 16px tiles). `scripts/rescale-png.js` redraws the used area at 2x as `src/assets/overworld.png` (see the catalog for the command), so tile `[column, row]` on the pack is 32px tile `[column, row]` in the game, frame `row * 42 + column`.

Terrain is **blob-autotiled on the map's own cells** (not a dual grid). Grass (`TERRAIN_BASE_TILE`) fills every cell; each terrain in `TERRAIN_AUTOTILES` is drawn over it, with its border inside its own edge cells. Every set uses the same 7-column layout (strip, notched 3x3, plain 3x3), which the catalog diagrams. Water, sand beach and deep water come in **6 animation frames** laid 7 columns apart. The **dirt** path (`TERRAIN_AUTOTILES.dirt`) is the peach sand-patch set, which only has a _notched_ 3x3 (`block: [1, 3]`, `inner: [2, 4]`): its outer corners and edges are clean, but every quarter that would be `'full'` has a ~8x6px notch in its inner corner, so dirt two or more tiles wide shows grass holes in its middle. One-tile-wide paths (only `'outer'` and `'vertical'`/`'horizontal'` quarters) are clean. A wider path needs a full sand tile added to the sheet (e.g. in the empty row 7) and a `full` option in `autotile.ts`.

## Seasonal terrain sheets: overworld-autumn.png, overworld-winter.png, overworld-underworld.png, overworld-starship.png

Four more copies of the overworld sheet, 1344x2016 with **exactly the same layout** as `overworld.png`, so every `[column, row]` and frame number works on all five. `SEASON_TERRAIN_SHEETS` in `tileset.ts` names their texture keys (`overworld-autumn`, `overworld-winter`, `overworld-underworld`, `overworld-starship`), `TERRAIN_SHEET_URLS` in `sprites.ts` their files; a level's `season` (from its region) picks the one GridScene draws terrain, forests, mountains and buildings from. The cursor and movement arrow always come from the summer sheet. `map-props.png` (bridges, gates, fords, spikes) has no seasonal copy.

- **Winter** (`overworld-winter.png`): the pack's snow tilesheet (`Tactical RPG Overworld Pack - Snow Tilesheet.png`, 3072x3072 at 3x, same used area as the green one), rescaled with the same `rescale-png.js --from 3 --to 2 --crop 672x1008` command. Snow grass, icy lavender water, grey-blue pines and round trees, a pink dirt path, and snow-roofed buildings in every palette.
- **Autumn** (`overworld-autumn.png`): `overworld.png` with its greens swapped and its forests bare, made by `node .claude/skills/tileset/scripts/recolor-season.js autumn src/assets/overworld.png src/assets/overworld-autumn.png` (rerun it after changing the summer sheet; the script's `SEASONS` holds each season's color rules): grass `#b7d463` / `#ceda62` to golden `#e0a24e` / `#ebb55c`; mountain tufts and the grass lip under buildings and walls `#84b14d` to rust `#c06a32`; tree shade `#3b7d4f` to `#8a3424` (terrain rows 0–32 only, since the green building palette uses it too); the dark-grass meadow set (columns 8–14, rows 3–7) deeper, `#a94f27` / `#c06a32`. The forest tiles `[0, 1]`, `[1, 1]`, `[2, 1]` and their peak variants `[8, 1]`, `[9, 1]`, `[10, 1]` are redrawn from 16px ASCII art in the script (`BARE_TREES`): the same number of trees as the leafy tile (3 conifers, 3 round trees, 2 big trees), each at the leafy tree's spot, bare branches (`#8f4d57` trunk, `#5e2f36` branches) over a small pile of fallen leaves; the peak variants keep their mountain peak on top. Water, sand, mountains and buildings are untouched.
- **Underworld** (`overworld-underworld.png`): `recolor-season.js underworld` (same command, `underworld` and `overworld-underworld.png`). Dead grey-brown ground (`#6b5c50` / `#766656`), charred meadows (`#3f3330` / `#524240`), the bare forests in charcoal with ash piles, dark grey mountains with ash caps, and every water set as lava (water `#d23c1e`, deep `#a3241a`, shade `#7a1a18`, ripples `#ef7a26`, foam `#ffcf4a` / `#ffa733`), its rocky and sandy shores black rock and ash, the dirt path ash `#8f7d70`. Water colors only change in rows 3–32, since the mountains (rows 0–2) share two of them. Buildings untouched.
- **Starship** (`overworld-starship.png`): `recolor-season.js starship`. A habitable starship deck: the base grass tile `[0, 0]` redrawn as steel deck plating (`DECK`, seams on its top and left edges so cells read as plates, rivets in the corners); the dark-grass meadow kept green (hydroponic beds); water as glowing cyan coolant with metal rims; deep water as viewports onto space (`#121628`, its ripples as stars `#e8f0ff`); the sand-patch dirt path as a pale walkway with yellow edge lights; the beach sets as metal. Forest tiles are hydroponic planters (`PLANTERS`, green plants in metal planters, one per tree). Mountains are machinery stacks: `MACHINE_CAP` (a dome and beacon) on `[4, 0]` / `[5, 0]`, three `MACHINE_BODIES` (glowing panel, vents, side pipes) on the body tiles, body + cap on the peak-below tiles `[5, 1]` / `[7, 1]`, `MACHINE_COMPACT` + cap on `[6, 0]` / `[7, 0]`, and the cap over the planters on the forest-peak tiles `[8–10, 1]`. Building and wall lip `#84b14d` is a deck shadow `#5c6578`. Buildings are redrawn too (`SHIP_BUILDINGS`, one 16px design per `BUILDING_ART` kind: hab pod, bunker, holo shrine, radar dish, supply depot, factory, hydroponic farm, energy pool, vault, drill rig, comm spire, command center; tall kinds with a `<kind>Top`), painted into every palette's column with that palette's accent (`SHIP_ACCENTS`) on its stripes, and every flag tile cleared. The script reads `BUILDING_ART` and `BUILDING_PALETTES` from `src/game/tileset.ts`. Each palette's rampart group (5 rows x 6 columns from its `wall` tile) is redrawn as a steel bulkhead: every group has the same shapes as a-stone's, so the summer a-stone group's color at each pixel names its role (`SHIP_WALL_ROLES`: outline, steel top, dark face, deck shadow), and its highlight dashes and door take the palette's accent, so walls are trimmed with lit strips in the team color. Its gateways are on its own props sheet, `map-props-starship.png` (written beside the output from `map-props.png`, same layout; `SEASON_PROPS_SHEETS` in `tileset.ts` picks it): each palette's posts are steel piers with its accent light, a beam across the opening and a lit walkway floor (`SHIP_GATE_POSTS`), and its lintel a glowing energy beam (`SHIP_GATE_LINTEL`); ford and spikes are copied as they are. `map-preview.ts --season` uses a season's props sheet when there is one.

`map-preview.ts --season autumn|winter` renders maps from these sheets.

## Inspecting art

Images this small are unreadable when viewed directly — dump them as ASCII:

```sh
node .claude/skills/tileset/scripts/dump-png.js src/assets/units/Villager_01_Idle.png src/assets/units/Soldier_03_Idle.png
node .claude/skills/tileset/scripts/dump-png.js --tile 32 src/assets/overworld.png:0     # one tile of a sheet
node .claude/skills/tileset/scripts/dump-png.js --colors src/assets/units/Villager_01_Idle.png                # colors + pixel counts
```

Each distinct color gets its own character (most common first), with a `char=hex` legend under the image; transparent pixels are spaces. Characters are assigned per image, so the same character can mean different colors in two dumps.

To _look_ at a block of a sheet (e.g. when cataloging new tiles), render it as a zoomed contact sheet and view the PNG; it labels column/row numbers and prints each tile's opaque bounding box. To check how overlays stack, compose tiles into a little scene (`/` separates rows, spaces cells, `+` layers bottom to top):

```sh
node .claude/skills/tileset/scripts/sheet-grid.js --scale 3 src/assets/overworld.png <scratchpad>/grid.png 0 0 12 2   # columns 0-12, rows 0-2
node .claude/skills/tileset/scripts/compose-tiles.js <scratchpad>/scene.png "0,0+4,0 0,0 / 0,0+4,1 5,9+12,1"
```

To judge an autotile set as the game will draw it, `autotile-preview.ts` runs a little `#`/`.` map through `src/game/autotile.ts` over grass (`--over c,r=X` stamps a sheet tile on cells marked X):

```sh
node .claude/skills/tileset/scripts/autotile-preview.ts --block 1,33 --inner 2,34 --over 5,34=G <scratchpad>/walls.png "......./.##G##./.#...#./.#####./......."
```

To judge the procedural map generator's output, `map-preview.ts` renders `generateMap` maps for some seeds side by side, drawn the way GridScene draws them (terrain, walls, crossings, forests, mountains and buildings in one palette; no ginkgos). `--archetype <type>` picks a map type (`mapArchetypes.ts`), `--terrain '<json>'` sets other terrain options, and `--units N` stands N warriors on the deployment zone (tinted) and N skeletons on enemy spots:

```sh
node .claude/skills/tileset/scripts/map-preview.ts --scale 1 --palette a-stone [--season winter] <scratchpad>/maps.png 1 2 3
```

`realm-preview.ts` does the same for the Warband overworld (`generateRealm` in `src/game/warband/realm/`): it renders whole realms for some seeds the way the overworld screen paints them (the parchment map from `getRealmInk` and `paintRealmInk`, with each site's icon stood on its tile), one under the other, and prints each realm's sites (id, kind, biome, region) and the names lettered on it:

```sh
node .claude/skills/tileset/scripts/realm-preview.ts <scratchpad>/realms.png 1 2
```

`scripts/rescale-png.js --from N --to M [--crop WxH] in.png out.png` changes the scale of upscaled pixel art (it checks every NxN block is one color). `dump-png.js` exports `decode` and `encode` (rows of RGBA pixels to and from PNG) for other scripts.

## How the code uses the art

- **`src/game/tileset.ts`** — the only place art is chosen. Everything else refers to art by name (terrain, unit class, UI element, arrow piece). `TERRAIN_SHEET` (texture key and size), `TERRAIN_BASE_TILE`, and `TERRAIN_AUTOTILES` (per terrain: `block`, the plain 3x3's top-left tile; `inner`, the all-corners-notched tile; `animation`) place terrain as `[column, row]` tiles. `CURSOR_ANIMATION` lists the cursor's two sheet tiles and how long each shows, and `ARROW_TILES` gives each arrow piece its sheet tile. `UNIT_SPRITES` (by unit class, via `getUnitSprite(unitClass)` with a `DEFAULT_UNIT_SPRITE` fallback) names each class's **unit art** — a unit looks the same on either team, `unitSheetKey(art, animation)` turns that into the texture key of one of its sheets, `UNIT_SHEET` says how unit sheets are cut (a row per facing) and `UNIT_ANIMATIONS` how each animation is timed. `FOREST_ART` and `MOUNTAIN_ART` list the overlay variants for forest and mountain cells, `BUILDING_ART` places each building kind (`src/game/buildings.ts`), and `BUILDING_PALETTES` names the ten building colors (set A's light gray is called `a-stone`). A level draws every building and wall in one palette, so colors never mix. Never put frame numbers or keys directly in scenes or logic.
- **`src/game/mapArt.ts`** — pure picking of one-tile overlays from the sheet: `getFeatureSprites` (forests and mountains, with the mountain stacking rule from the catalog), `getBuildingSprites` (buildings, tall tops and flags in a palette) and `getWallAutotile` (a palette's rampart set). Each sprite has a layer: `ground` (under units), `cap` (art poking into the cell north) or `roof` (over units).
- **`src/assets/sprites.ts`** — `SPRITE_URLS`, texture key → imported image URL for every standalone sprite. GridScene preloads each under its key; the React `UnitSprite` component shows one by key. A new sprite means importing its file here and naming its key in `tileset.ts`. `tileset.test.ts` checks every key in `tileset.ts` has a URL.
- **`src/game/autotile.ts`** — pure autotile logic. Each terrain cell is drawn as four quarter tiles; `getQuarterShapes(grid, x, y, terrain)` names each quarter's shape from its two side neighbors and the diagonal between them (`'outer'`, `'horizontal'`, `'vertical'`, `'inner'`, `'full'`). That covers all 47 blob combinations. Cells off the map take the nearest cell on it, so terrain continues past the edge. `getShapeTile` picks which sheet tile's same quarter draws a shape, and `getQuarterFrames` turns that into frame numbers on the sheet cut into 16px quarters (2 x 42 per row), shifted by `columnStride` for each animation frame.
- **`GridScene`** — `renderTerrain` lays a 32px grass tilemap, then one 16px-tile layer per autotiled terrain from `getQuarterFrames` (`TERRAIN_AUTOTILES` plus `wall` in the level's palette), precomputing every animation frame and stepping the layer's tile indices on a timer. `renderMapSprites` draws `mapArt.ts`'s overlays as sheet frames. `addTileSprite(x, y, key)` draws a sprite stretched to exactly one tile, so 16px and 32px images both fit. Every unit is outlined in its team's color by `addUnitOutline` (`src/scenes/unitOutline.ts`; colors and width are `UNIT_OUTLINE` in `tileset.ts`), a white silhouette ring built per sheet from the art's alpha (`getOutlineMask`, 1 sheet pixel wide, cut at frame edges) and tinted. The unit sprites have no shadows of their own, so `addUnitShadow` (`src/scenes/unitShadow.ts`) puts a translucent pixel ellipse under each unit's feet. Its size, position and opacity are `UNIT_SHADOW` in `tileset.ts`, set for where the units' feet touch the ground (see Units above), so retune it if new unit art stands differently. GridScene loads the overworld sheet as a 32px spritesheet, so the tilemaps use it whole and the cursor and arrow sprites draw single frames of it. Bosses and elites (`Unit.rank`) also get a badge from `addRankBadge` (`src/scenes/rankBadge.ts`): `RANK_BADGES` in `tileset.ts`, 11x11 pixel art written as rows of palette letters (boss: a white skull on a red plate; elite: a gold star on a violet plate, both outlined `#1a0d12`), drawn at 1 world pixel per art pixel (finer than the 2x unit art, so it reads as a HUD mark) at tile pixel (21, 0), over the art's top-right corner. The React `RankBadge` draws the same rows as SVG. No art-choice rules in the scene.

## Rules when changing art

1. If you decode something about an image that isn't written down here (a new sheet's layout, what a sprite shows), add it to this file so it isn't re-derived.
2. Keep frame numbers and sprite keys in `tileset.ts`, and image imports in `sprites.ts`. Keep tile-selection rules as pure functions in `src/game/` with Vitest tests (see `autotile.test.ts`): test shape names, plus one test pinning the actual frame numbers.
3. New art should be 32x32, or a clean fraction of it (16x16 is drawn at 2x), so it drops onto the grid without special-casing.
4. An autotile set only borders its own cells against _anything else_, so any number of terrains can each be a layer over grass. Two sets that meet directly (e.g. sand next to water) just butt their borders together.
5. To preview terrain art without a browser, compose tiles with `decode` from `scripts/dump-png.js` and the pure `autotile.ts` functions into a PNG, and view that.
